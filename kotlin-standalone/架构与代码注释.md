# Kotlin 预览工程 · 架构与代码注释（独立文档）

> 本文是**独立注释文档**，不写进 Java 主工程、也不参与 APK 构建。
> 只解释 `kotlin-standalone/` 里「有哪几层、每个文件干什么、每个函数怎么工作」。
> 运行命令与验证步骤见同目录 `README.md`。

---

## 一、整体框架

### 1. 定位

本工程是**纯 JVM 的解析层参考实现**：把 Java 版 `com.wgj.switchquery.ui.ResultRefiner`
和四个数据模型用 Kotlin 1:1 重写，输入是交换机命令行原样回显，输出是给人看的精简文本。
不包含 Android UI、SSH/Telnet 连接、存储与登录，所以不依赖 Android SDK。

### 2. 分层

```
┌───────────────────────────── 运行层  Main.kt ─────────────────────────────┐
│   main(args)  ──┬─ selfTest()      9 个断言，验证解析文案                  │
│                 ├─ demo()          打印两段示例输出                        │
│                 └─ parityDump()    批量跑 samples/，写对比文本              │
└───────────────────────────────────┬───────────────────────────────────────┘
                                    │ refine(type, raw)
┌───────────────────────────────────▼───────────────────────────────────────┐
│ 解析层  refiner/ResultRefiner.kt                                          │
│   refine() 分派 → 6 个类型解析函数 + 5 个共用工具函数                       │
│   只依赖 JDK：Regex / StringBuilder / TreeSet / String                     │
└───────────────────────────────────┬───────────────────────────────────────┘
                                    │ 只做类型定义与展示字段
┌───────────────────────────────────▼───────────────────────────────────────┐
│ 模型层  model/Models.kt                                                   │
│   SwitchType / SwitchDevice / Project / PortDescriptor                    │
└───────────────────────────────────────────────────────────────────────────┘

验证层（独立于上面三层，只在对比时使用）
   tools/ParityDump.java  → 编译 Java 原版 ResultRefiner，输出同格式基准文本
   samples/*.txt          → 12 份真实厂商回显，作为两边共同的输入
```

**一次解析的数据流**：

```
交换机原始回显（String）
        │  refiner.refine(type, raw)
        ▼
   raw 为空/全空白 ? ──是──▶ "（无返回内容）"
        │否
        ▼
   按 type 分派（port_up / port_vlan / port_optical / port_errors / vlan_ip / all_vlans）
        │  未知 type
        ▼          ▼
   对应解析函数   raw.trim() 原样返回
        │
        ▼
   精简文本（固定中文文案 + 固定分隔符），供界面或对比文件使用
```

### 3. 三种运行模式的调用链

| 模式 | 命令 | 入口 | 调用链 |
|---|---|---|---|
| 自检 | `run` | `selfTest()` | 内置 9 段回显 → `refine()` → 与期望字符串逐字比较，失败 `exitProcess(1)` |
| 示例 | `run --args="demo"` | `demo()` | 锐捷 Trunk、华为 Access 两段示例 → `refine()` → 打印 |
| 对比 | `run --args="parity samples kotlin_out.txt"` | `parityDump()` | 遍历 `samples/*.txt` → `refine()` → 转义后逐行写 UTF-8 文件 |

## 三、逐文件详解

### 3.1 `settings.gradle.kts`

```kotlin
rootProject.name = "switchquery-kotlin-preview"
```

- 整个文件只有一行：给独立工程起名。
- **关键点**：没有 `include(...)`，也不引用根工程；Gradle 只有在 `-p kotlin-standalone`
  时才会读到它，因此 `gradlew projects` 在根目录仍然只显示 `:app`。

### 3.2 `build.gradle.kts`

| 配置 | 作用 | 备注 |
|---|---|---|
| `kotlin("jvm") version "2.1.0"` | Kotlin JVM 插件 | 只要 JDK，不要 Android |
| `application` | 生成 `run` 任务与启动脚本 | `mainClass = com.wgj.switchquery.MainKt` |
| `repositories { mavenCentral() }` | 依赖来源 | Kotlin stdlib 由插件自动带入 |
| `kotlin { jvmToolchain(17) }` | 编译与运行都用 JDK 17 | 与主项目一致，避免 JDK 25 的兼容问题 |
| `tasks.jar { manifest ... }` | 打出可执行 jar | `java -jar` 需自带 stdlib，一般用 `run` 或 `installDist` |
| `tasks.named<JavaExec>("run") { jvmArgs(...) }` | 控制台固定 UTF-8 | 中文文案不依赖终端代码页，写文件也显式 UTF-8 |

### 3.3 `Main.kt`（141 行）

| 函数 | 可见性 | 输入 | 输出 / 行为 |
|---|---|---|---|
| `main(args)` | public | 命令行参数数组 | 读 `args[0]`：`parity` / `demo` / 其他（含空）→ 自检。**不做参数校验以外的业务逻辑** |
| `escape(s)` | private | 任意字符串 | 把 `\`、`\r`、`\n`、`\t` 转成字面量，保证对比文件是**单行可 diff** 的 |
| `parityDump(dir, outFile)` | private | 样例目录、输出文件（可空） | 按文件名排序遍历 `*.txt`；`name|type|escaped(result)` 每行一条；`outFile` 为空则打印到控制台；目录为空 `exitProcess(2)` |
| `demo()` | private | 无 | 两段硬编码回显（锐捷 Trunk、华为 Access），打印精简结果，用于人工直观查看 |
| `selfTest()` | private | 无 | 9 个内置断言；全过打印「全部用例通过」，有失败打印期望/实际并 `exitProcess(1)` |

**`parityDump` 的两个约定**：

1. `type` 取自文件名 `__` 之前（`port_vlan__h3c_permitted.txt` → `port_vlan`），
   与 `refine()` 的分派键一致；
2. 读取用 `File.readText()`（Kotlin 默认 UTF-8），写出用 `File.writeText()`（默认 UTF-8），
   所以结果不受 Windows 控制台代码页影响。

**自检 9 个用例**（期望值与 Java 版逐字对齐）：

| # | 用例 | 类型 | 覆盖点 |
|---|---|---|---|
| 1 | 锐捷 Trunk 多行 VLAN 列表合并 | `port_vlan` | 表格式 + 续行 `2001-2020,2301-2320` / `2395` 合并 |
| 2 | 华为 Access 端口 | `port_vlan` | `display port vlan` 表格行 |
| 3 | 无 VLAN 信息 | `port_vlan` | 兜底文案「未获取到VLAN信息」 |
| 4 | 端口 UP | `port_up` | `Current state: UP` |
| 5 | 管理性关闭 | `port_up` | `is administratively down` |
| 6 | 错误包求和 | `port_errors` | 5 input + 3 output = 8 |
| 7 | VLAN IP 与掩码 | `vlan_ip` | `10.1.1.1/24` → 点分掩码 |
| 8 | 光功率单通道 | `port_optical` | 表头 + 一行数据 |
| 9 | 空输出 | `port_vlan` | 空白输入 → 「（无返回内容）」 |

### 3.4 `Models.kt`（65 行）

| 类型 | 类型 | 字段 / 行为 | 说明 |
|---|---|---|---|
| `SwitchType` | `enum class` | `HUAWEI("华为")`、`H3C("H3C")`、`RUIJIE("锐捷")`、`UNKNOWN("未知")` | `label` 直接给界面展示，替代 Java 的 `getLabel()` |
| `SwitchDevice` | `data class` | id、name、ip、port、username、password、core | `data class` 自带 `equals/hashCode/copy`，替代 Java 的 getter/setter |
| `Project` | `data class` | id、name、core、nodes | `withNode()` 返回 `copy(nodes = nodes + node)`，**不可变列表**；Java 版是可变 `addNode` |
| `PortDescriptor` | `class` | rawName、prefixType、prefixAbbr、portNumber、description、status、adminStatus、displayName | 核心是「命令行用 rawName、界面用 displayName」 |
| `PortDescriptor.StatusColor` | `enum class` | `GREEN` / `DEFAULT` / `RED` | 与 Java 版同名枚举 |
| `PortDescriptor.statusColor()` | 方法 | 无参 | `up` → GREEN，`down` → DEFAULT，其他 → RED（大小写不敏感） |

**`displayName` 生成规则**（与 Java 版一致）：

```
description 非空 → "[prefixAbbr] description"      例：[GE] 测试
description 为空 → "[prefixAbbr] portNumber"       例：[GE] 1/0/1
```

**`@JvmField` 的用途**：让 Kotlin 属性以字段形式暴露（不生成 getter/setter），
与 Java 版 `public final String rawName` 的访问方式一一对应，便于将来混编或对照。

### 3.5 `ResultRefiner.kt`（415 行，核心）

入口是一个 Kotlin `object`（单例），`refine()` 标了 `@JvmStatic`，因此 Java 侧也能
`ResultRefiner.refine(...)` 静态调用，签名与 Java 原版保持同一形态。

#### 3.5.1 函数总表

| 函数 | 类型 | 输入 | 输出 | 职责 |
|---|---|---|---|---|
| `refine(type, raw)` | public | 功能类型、原始回显（可空） | 精简文本 | 空值保护 + 6 类分派 + 未知类型 `trim()` |
| `refinePortUp(raw)` | private | 原始回显 | 端口状态文案 | 两条正则依次尝试，识别 UP / DOWN / 管理性关闭 |
| `refinePortVlan(raw)` | private | 原始回显 | VLAN 文案 | **8 级优先级链**，见 3.5.2 |
| `findMultiLineVlanList(raw)` | private | 原始回显（可空） | VLAN 列表或 null | 兜底：全文本扫描，取「条目最多」的多行列表 |
| `extractH3cVlanList(raw, keyword)` | private | 回显、关键字（`vlan permitted` / `vlan passing`） | 列表或 null | 取关键字行 + 折叠续行，清理 `(default vlan)` |
| `appendVlanContinuations(raw, fromIndex, initial)` | private | 回显、起始下标、首段 | 合并后的列表 | 从匹配结束位置往后拼接续行，去空白 |
| `refineOptical(raw)` | private | 原始回显 | 光功率文案 | 三级策略提取 RX/TX，单通道/多通道两种排版 |
| `numbersOf(line)` | private | 一行文本 | 数字列表 | 提取全部整数/小数（含负号） |
| `extractCurrentSection(raw)` | private | 原始回显 | 子串 | 截取 `current diagnostic parameters` 到 `threshold/alarm` 之间 |
| `refineErrors(raw)` | private | 原始回显 | 错误包总数 | input/output 两种正则形态 + 「N errors」兜底求和 |
| `findCount(raw, regex)` | private | 回显、正则 | Long（缺失 -1） | 取第 1 组数字并转 Long |
| `refineVlanIp(raw)` | private | 原始回显 | IP + 掩码 | 支持 `a.b.c.d/nn`、`a.b.c.d mask`，`0.0.0.0` 视为未配置 |
| `prefixToMask(prefix)` | private | 前缀长度字符串 | 点分掩码 | 位运算生成；非法前缀原样返回 `/nn` |
| `refineAllVlans(raw)` | private | 原始回显 | VLAN 列表文案 | 三个来源汇总 + 去重排序 + 每行 10 个 |
| `extractVlansFromText(set, text, numPattern)` | private | 集合、文本、数字正则 | 原地写入集合 | 先展开范围（`-`/`–`），再收集单个 ID |
| `addVlan(set, s)` | private | 集合、字符串 | 原地写入 | 只接受 1..4094 |
| `addVlanRange(set, startStr, endStr)` | private | 集合、起止字符串 | 原地写入 | 自动翻转起止；跨度 > 500 或越界则丢弃 |

#### 3.5.2 `refinePortVlan` 的 8 级优先探测 + 1 级兜底（从上到下，命中即返回）

1. `pvid` + `VLAN permitted/Passing` → `端口VLAN（Trunk）：Native X  放行 ...`
2. `pvid` + `Tagged VLAN ID` → 同上，列表用 tagged
3. 只有 `permitted` → `端口VLAN（Trunk）：放行 ...`
4. 只有 `pvid` → `端口VLAN：X`（Access 常见）
5. `access vlan X` 行式 → `端口VLAN：X`
6. **锐捷表格式**：`端口名 [编号] enabled access|trunk 接入VLAN Native [Protected] 列表`；
   Access 直接取第 2 组，Trunk 取 Native + 续行合并
7. **华为 `display port vlan` 表格式**：`端口 linkType pvid [列表]`；
   Access 只给 pvid，Trunk 给 Native + 续行合并
8. 行式 `Native VLAN` / `Allowed VLANs` → 拼接
9. 兜底：`findMultiLineVlanList` 扫全文取条目最多的多行列表；再不行返回「未获取到VLAN信息」

> 设计原因：不同厂商、不同型号的回显格式差异极大，按「信息最完整」的顺序试探，
> 前面的分支能拿到 Native + 放行列表，后面的分支只做保底，避免某一种格式把其他格式挤掉。

#### 3.5.3 折行续接的三个函数（本项目最容易出错的地方）

交换机终端宽度有限，VLAN 列表会被折成多行：

```
 VLAN permitted          : 20,23,120-139
                            2001-2020,2301-2320
                            2395
```

| 函数 | 判断续行的规则 | 拼接方式 | 用途 |
|---|---|---|---|
| `extractH3cVlanList` | 行首是数字，且整行只含 `数字/逗号/空格/连字符`（可带一个尾逗号） | 用**空格**拼 | H3C `VLAN permitted` / `VLAN Passing` |
| `appendVlanContinuations` | 同上 | 用**逗号**拼，最后删掉所有空白 | 锐捷/华为表格式 |
| `findMultiLineVlanList` | 同上 | 用**逗号**拼，最后删掉所有空白 | 未知格式兜底 |

**共同点**：都从正则匹配的 `end()` 位置往后扫（Kotlin 写作 `range.last + 1`），
**遇到空行必须 `continue` 而不是 `break`** —— 因为 `(.*)$` 的匹配结束位置落在换行符之前，
`substring` 切出来的第一段就是空串；若按空行中断，续行永远拼不上（v1.7.8 修的正是这个 bug）。

#### 3.5.4 `refineOptical` 的三级提取策略

| 策略 | 适用场景 | 做法 |
|---|---|---|
| 1 关键字锚定 | 华为/H3C 表头式 | 每行找 `RX power` / `TX power` 后的第一个数字；先剔除 `threshold/alarm/warn/...` 行 |
| 2 锐捷 `(OK)[Cn]` 标记 | 锐捷 100G/40G 多通道 | 全局匹配 `数值(OK)[Cn/` 作为 RX，`AP] 数值` 作为 TX |
| 3 表头后数字流 | 只有表头没有关键字的格式 | 找到含 `rx`+`power` 且无数字的表头行；H3C `[channel]` 段按行取倒数第二/倒数第一，`[module]` 段取最后一行的这两个数 |

输出格式：

```
单通道：RX 光功率：-5.20 dBm
        TX 光功率：-3.10 dBm
多通道：光功率（共 2 通道）：
        通道1：RX -13.60 dBm / TX -2.10 dBm
        通道2：RX -13.20 dBm / TX -2.30 dBm
```

### 3.6 `tools/ParityDump.java`（对比基准）

- **为什么要有它**：直接编译主工程里的 `app/src/main/java/com/wgj/switchquery/ui/ResultRefiner.java`，
  用同一批 `samples/*.txt` 跑一遍，把结果写成与 Kotlin `parity` 模式**完全相同**的文本格式，
  这样 `Get-FileHash` 相等就说明两版行为逐字节一致，不依赖人眼。
- **输出格式**：`文件名去扩展名|类型|转义后的结果`，每行一条，按文件名排序，UTF-8。
- **编译方式**：`javac -sourcepath app\src\main\java`，只编译这一个工具类，不改主工程任何文件。
- **转义函数 `esc`**：与 `Main.kt` 的 `escape` 规则一致（`\`、`\r`、`\n`、`\t`），
  保证多行结果压成单行、便于 diff。

## 四、调用关系（按文件）

```
Main.kt
  ├─ selfTest() ────────────────┐
  ├─ demo() ────────────────────┤→ ResultRefiner.refine(type, raw)
  └─ parityDump() ──────────────┘      ├─ refinePortUp
                                       ├─ refinePortVlan
                                       │    ├─ extractH3cVlanList
                                       │    ├─ appendVlanContinuations
                                       │    └─ findMultiLineVlanList
                                       ├─ refineOptical
                                       │    ├─ extractCurrentSection
                                       │    └─ numbersOf
                                       ├─ refineErrors
                                       │    └─ findCount
                                       ├─ refineVlanIp
                                       │    └─ prefixToMask
                                       └─ refineAllVlans
                                            ├─ extractVlansFromText
                                            ├─ addVlan
                                            └─ addVlanRange

Models.kt  ← 只被解析层/界面层引用，不反向依赖任何人
tools/ParityDump.java → 主工程 Java 版 ResultRefiner（仅对比时）
```

依赖方向单一：`Main → ResultRefiner → Models`，没有任何一环回头依赖 `Main`；
解析层也不引用 Android 或连接层，因此可以脱离 APP 单独跑。

## 五、Kotlin 与 Java 实现的差异（移植时踩过的坑）

| # | 差异点 | Java 写法 | Kotlin 写法 | 影响 |
|---|---|---|---|---|
| 1 | 未参与匹配的分组 | `m.group(n)` 返回 `null` | `groupValues[n]` 返回 `""` | 必须用 `m.groups[n]?.value`，否则空串会被当成有效值 |
| 2 | 匹配结束位置 | `m.end()` | `m.range.last + 1` | 续行合并的起点差 1 位就会漏行/错行 |
| 3 | 空行处理 | `if (t.isEmpty()) continue` | 同 | 折行续接必须跳过空行，不能 `break` |
| 4 | 死分支告警 | Java 不提示 | Kotlin 提示「条件恒为 false」 | 兜底分支里 `pvid != null` 本就不可能成立，已改成等效写法 |
| 5 | 集合可变化 | `List` + `addNode()` | `List` + `copy()` 返回新对象 | `Project.withNode()` 语义更安全，不共享可变状态 |
| 6 | 常量与字段 | `public final` / getter | `val` / `@JvmField` | 对照时按字段名直接访问即可 |

## 六、扩展指南：新增一个查询类型要改哪里

以新增 `mac_table`（MAC 表查询）为例，共 5 步，**全部只在本工程内**：

1. `ResultRefiner.refine` 的 `when` 加一支：`"mac_table" -> refineMacTable(raw)`；
2. 在 `ResultRefiner.kt` 里新增 `private fun refineMacTable(raw: String): String`，
   只做字符串解析，输出固定中文文案；
3. `samples/` 放 1~2 份真实回显，文件名 `mac_table__xxx.txt`；
4. `Main.kt` 的 `selfTest()` 加一条 `check(...)`，期望值先按 Java 版行为确定；
5. 重跑两件事：`run`（自检全 PASS）与 `parity` + `ParityDump`（哈希一致）。

> 若该类型将来要进主工程，先在 Java 版实现并验证，再回填本工程做一致性对比，
> 保证两套代码始终「同输入同输出」。
